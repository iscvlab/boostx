# `/contextx` (Context & Compaction Diagnostic)

Inspect the active Antigravity conversation transcript (`transcript.jsonl`), determine the exact **Context Compaction Round**, **Active Window Pressure (`steps_since_compaction`)**, total session steps, and evaluate the risk of memory drift and hallucination.

Portable across Windows, macOS, and Linux. Zero external dependencies (Python standard library only).

Red failure modes to prevent:
1. Pushing long pair-programming sessions past Round 2+ where the model suffers from silent memory degradation and hallucinations.
2. Incurring unexpected IDE gRPC/session timeout crashes from bloated conversation transcripts.
3. Guessing the compaction count from memory or falsely counting tool outputs/subagent logs as compaction boundaries.

## Standard Operating Procedure (Every Run)

### Step 1: Execute the Diagnostic Script

Run the deterministic context analyzer ([`scripts/check_context.py`](scripts/check_context.py)) via the Global Customizations Root:

* **Windows (PowerShell)**:
  ```powershell
  python "$env:USERPROFILE\.gemini\config\skills\contextx\scripts\check_context.py"
  ```
* **macOS / Linux**:
  ```bash
  python3 ~/.gemini/config/skills/contextx/scripts/check_context.py
  ```

*(Optional: pass `--conv-id <id_or_prefix>` if targeting a specific session, or `--json` for structured output. By default, `check_context.py` automatically filters out isolated subagent transcripts so it always inspects the active main user conversation).*

### Step 2: Evaluate the 2D Health Rubric (Cumulative Round × Active Window Pressure)

The script parses `transcript.jsonl` `CHECKPOINT` boundaries (typically triggered every ~160–180 steps) and evaluates both **Cumulative Compaction Drift** and **Active Window Load**:

| Compaction Round | Active Window / Total Steps | Health Level | Memory Risk | Recommended Action |
| :---: | :---: | :--- | :--- | :--- |
| **Round 0** | `< 100` active (`< 120` total) | 🟢 **HEALTHY** | None (100% full context retention) | Continue work in current chat. |
| **Round 1** | `< 130` active (`120–249` total) | 🟡 **NOMINAL** | Low (recent history preserved) | Continue work; keep edits focused. |
| **Round 2** | `< 120` active (`250–449` total) | 🟠 **CAUTION** | Moderate (early constraints summarized twice) | Safe to finish current task, then run [`/kickoffx`](../kickoffx/SKILL.md). |
| **Round 3+** | `≥ 120` in Round 2 or `≥ 450` total | 🔴 **CRITICAL** | High (multi-pass truncation & timeout risk) | **Start a fresh chat immediately via [`/kickoffx`](../kickoffx/SKILL.md).** |

### Step 3: Present Scorecard & Guide Next Step

1. Output the markdown scorecard generated by `check_context.py`.
2. If status is **CAUTION** or **CRITICAL**:
   * Alert the user about cumulative compaction and active window pressure.
   * Advise the user: *"Run [`/kickoffx`](../kickoffx/SKILL.md) to verify document sync, review next-phase options, and generate a pristine prompt for your fresh conversation."*
3. If status is **HEALTHY** or **NOMINAL**:
   * Confirm that context is clean and proceed with normal task execution.
