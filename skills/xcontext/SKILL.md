# `/xcontext` (Context, Compaction & Token Telemetry Diagnostic)

Inspect the active Antigravity conversation transcript (`transcript.jsonl`) and SQLite step databases (`conversations/*.db`), determine the exact **Context Compaction Round**, **Active Window Pressure (`steps_since_compaction`)**, **Session & Cross-Platform Token Telemetry** (across Antigravity 2.0, Antigravity IDE, and Antigravity CLI), and evaluate the risk of memory drift and hallucination.

Portable across Windows, macOS, and Linux. Zero external dependencies (Python standard library only).

Red failure modes to prevent:
1. Pushing long pair-programming sessions past Round 2+ where the model suffers from silent memory degradation and hallucinations.
2. Incurring unexpected IDE gRPC/session timeout crashes from bloated conversation transcripts.
3. Guessing the compaction count from memory or falsely counting tool outputs/subagent logs as compaction boundaries.

## Standard Operating Procedure (Every Run)

### Step 1: Execute the Diagnostic Script

Run the deterministic context analyzer ([`scripts/check_context.py`](scripts/check_context.py)) via the Global Customizations Root:

* **Windows (PowerShell)**:
  ```powershell
  python "$env:USERPROFILE\.gemini\config\skills\xcontext\scripts\check_context.py"
  ```
* **macOS / Linux**:
  ```bash
  python3 ~/.gemini/config/skills/xcontext/scripts/check_context.py
  ```

*(Optional flags:
- `--conv-id <id_or_prefix>`: Target a specific session UUID or prefix.
- `--tokens` / `--days <N>` / `--all-time`: Aggregate cross-platform token telemetry (`input_tokens`, `cache_read_tokens`, `output_tokens`, `thinking_tokens`, and `subagents_spawned`) across Antigravity 2.0, Antigravity IDE, and Antigravity CLI, including a monthly breakdown table.
- `--json`: Output structured JSON.
By default, `check_context.py` automatically filters out isolated subagent transcripts so it always inspects the active main user conversation).*

### Step 2: Evaluate the 2D Health Rubric (Cumulative Round × Active Window Pressure)

The script parses `transcript.jsonl` `CHECKPOINT` boundaries (typically triggered every ~160–180 steps) and evaluates both **Cumulative Compaction Drift** and **Active Window Load**:

| Compaction Round | Active Window / Total Steps | Health Level | Memory Risk | Recommended Action |
| :---: | :---: | :--- | :--- | :--- |
| **Round 0** | `< 100` active (`< 120` total) | 🟢 **HEALTHY** | None (100% full context retention) | Continue work in current chat. |
| **Round 1** | `< 130` active (`120–249` total) | 🟡 **NOMINAL** | Low (recent history preserved) | Continue work; keep edits focused. |
| **Round 2** | `< 120` active (`250–449` total) | 🟠 **CAUTION** | Moderate (early constraints summarized twice) | Safe to finish current task, then run [`/xkickoff`](../xkickoff/SKILL.md). |
| **Round 3+** | `≥ 120` in Round 2 or `≥ 450` total | 🔴 **CRITICAL** | High (multi-pass truncation & timeout risk) | **Start a fresh chat immediately via [`/xkickoff`](../xkickoff/SKILL.md).** |

### Step 3: Present Scorecard & Guide Next Step

1. Output the markdown scorecard generated by `check_context.py`.
2. If status is **CAUTION** or **CRITICAL**:
   * Alert the user about cumulative compaction and active window pressure.
   * Advise the user: *"Run [`/xkickoff`](../xkickoff/SKILL.md) to verify document sync, review next-phase options, and generate a pristine prompt for your fresh conversation."*
3. If status is **HEALTHY** or **NOMINAL**:
   * Confirm that context is clean and proceed with normal task execution.
